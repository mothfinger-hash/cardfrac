### Feedback for the skill file

Two probe-method bugs surfaced this run and are worth folding into
`SKILL.md` step 3, because both produce **false "already in catalog"** or
**false "clean negative"** results:

1. `set_code` is **not unique across games** — `OP17` and `ST01` each collide
   between two TCGs. Every existence probe must include `game_type=eq.<game>`.
2. The Dragon Ball Fusion World `game_type` is **`dbfusion`**, not
   `dragonball`; and One Piece `set_code` values are **slugs**
   (`wings-of-the-captain`) for older sets while newer ones use `OP16`-style
   codes — so probe by `id like <prefix>-*` **and** `set_name ilike`, never by
   `set_code` alone.
